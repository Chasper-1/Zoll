# Спецификации движка-парсера

- Парсер ищет исключительно маркеры в тексте, не строя никаких токенов, ast и прочих конструкций.
- Поиск должен осуществляться преимущественно через simd поиск символов.
- Этап парсинга состоит из 3 этапов:
  - Первый этап, это поиск символов/маркеров в тексте, записывается их позиция исключительно.
  - Далее идёт, самый сложны этап, который может идти параллельно.
    - Сначало обязательно идёт соединение символов в маркер, потому что simd не умеет искать ** такие маркеры, а только * + \*, который надо отдельно превратить в ** цельный.
    - Далее идёт не слишком умная проверка на правила языка. Например, если был найден **, обязательно должен найтись и символ )) закрытия. Если его не найдено, этот найденный символ выбрасывается. Если нашлась конструкция \*\*...)), ей даётся ярлык в зависимости от того, что она делает. Далее, записывается диапазон этой конструкции включая маркеры обязательно, чтобы использовать эти данные позже.
  - Потом идёт этап распределения на ручки или в бд внутренюю, в зависимости от нужд. Отправка идёт асинхронно и никто не ждёт от другого ответа, это обязательно.

##  Клиент — редактор

- Клиент должен уметь принимать асинхронные данные, отправлять их так же асинхронно по предоставленным движком ручкам.


# SIMD-поиск синтаксических байтов

Первый этап парсера Zoll отвечает исключительно за быстрый поиск синтаксически значимых байтов. Он не определяет, что найденный байт означает, не строит маркеры и не занимается грамматикой.

Документ последовательно разбивается на SIMD-блоки по 32/64 байта. Для каждого блока SIMD загружает регистр и выполняет поиск интересующих байтов.

Результатом обработки блока являются:

`SIMD-регистр + битовая маска + абсолютное смещение блока`

Битовая маска имеет размер регистра. Если бит равен 1, соответствующий байт в регистре является найденным.

Например:

```
register:
[ a b c } d e * f g h i j ) ... ]


mask:
      1     1       1
      ↑     ↑       ↑
      3     6      12
```

При этом маска не хранит тип найденного символа. Она только указывает его положение внутри регистра. Сам байт берётся непосредственно из регистра по этой позиции.

Если начало блока находится на позиции 4096, результат преобразуется в:

```
position  byte
4100      }
4103      *
4108      )
```

Таким образом, первый этап передаёт дальше поток событий вида:

`(position, byte)`

Например:

```
(4100, '}')
(4103, '*')
(4108, ')')
```

Сам SIMD-слой при этом ничего не знает о синтаксисе Zoll. Для него существует только понятие «интересующий байт». Определение того, что означает последовательность найденных байтов, например )), }}, ** или другой маркер, выполняется следующим уровнем.

Главная задача этого этапа — одним проходом по большим блокам данных быстро получить координаты всех потенциально значимых байтов, не заставляя основной parser сканировать весь текст повторно.

При параллельной обработке каждый SIMD-блок сохраняет своё абсолютное смещение, поэтому результаты разных потоков можно независимо обрабатывать и затем объединять в порядке их позиций.

Это является первым уровнем parser pipeline:

текст
  ↓
SIMD scan
  ↓
register + mask + offset
  ↓
(position, byte)
  ↓
распознавание маркеров
  ↓
синтаксические конструкции
  ↓
зависимости и инкрементальный parsing

Ключевой принцип: SIMD отвечает только за поиск и координаты, следующий уровень — за понимание найденного.
